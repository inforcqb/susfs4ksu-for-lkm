01 / WHY LKM

保留原厂内核，
只加载需要的能力

传统 SUSFS 需要把补丁编进内核。LKM 版本把这件事拆开：内核保持原样，SUSFS 以模块形式按需载入，升级、回滚与审计都更轻。

内核零改动

以 .ko 形式运行，不重编译、不替换 GKI。系统 OTA 与内核分区保持原样，回滚只需卸载模块。

按 KMI 精准构建

覆盖 Android 12–17、GKI 5.10–6.18 的 8 个变体。每个产物都对应明确的 Android 版本与内核主版本。

KernelSU 原生路径

ksud insmod 直接加载；非 KernelSU 环境可使用 Release 自带的 susfs_insmod，同样无需重新打包内核。

开箱即用的模块包

刷入 KernelSU 模块 ZIP，开机按 /proc/sys/kernel/osrelease 自动选择 .ko，并带 expose_proc=1。

完整控制接口

expose_proc=1 暴露 /proc/susfs_*。路径、挂载、kstat、open redirect 与 mmap 规则统一由用户态下发。

公开、可审计

GPL-2.0-only。源码、KMI 构建矩阵、CFI 调用点检查与完整接口文档全部开放，方便核对每个变体。

02 / QUICK START

从下载到加载，
四步完成

先确认设备的 Android 版本与内核主版本，再选对应的 .ko。不确定时，优先使用模块 ZIP，让加载脚本自动匹配。

  1. 01

    确认 KMI

    读取 ro.build.version.release 与 /proc/sys/kernel/osrelease，对照下方矩阵选择产物。

  2. 02

    载入模块

    KernelSU 使用 ksud insmod；其他环境使用 Release 附带的 susfs_insmod。

  3. 03

    下发规则

    模块只负责加载，不设置任何 SUSFS 规则。规则由管理器或你的脚本写入 /proc/susfs_*。

  4. 04

    需要时卸载

    执行 rmmod susfs_guard_lkm 即可即时卸载；模块包则在管理器中停用或删除后重启。

提前加载：如果 SUSFS 规则必须在模块 post-fs-data 与挂载之前生效，以 root 执行 touch /data/adb/modules/susfs_guard_lkm/early_load 后重启。

adb · KernelSU 
# 1. 推送与设备 KMI 对应的 .ko
adb push susfs_guard_lkm-android15-6.6.ko /data/adb/loader/susfs_guard_lkm.ko

# 2. 通过 KernelSU 载入
adb shell su -c "ksud insmod /data/adb/loader/susfs_guard_lkm.ko"

# 3. 确认模块已载入
adb shell su -c "lsmod | grep susfs_guard_lkm"
设备上的目标路径可自定义；示例以 Android 15 / GKI 6.6 为例。
adb · susfs_insmod 
# 1. 推送模块与 Release 自带的加载器
adb push susfs_guard_lkm-android14-6.1.ko /data/adb/loader/susfs_guard_lkm.ko
adb push susfs_insmod /data/adb/loader/susfs_insmod

# 2. 赋予执行权限并载入
adb shell su -c "chmod 755 /data/adb/loader/susfs_insmod"
adb shell su -c "/data/adb/loader/susfs_insmod /data/adb/loader/susfs_guard_lkm.ko"

# 3. 卸载
adb shell su -c "rmmod susfs_guard_lkm"
非 KernelSU 环境依靠 susfs_insmod 在用户态完成符号解析与载入。

04 / DOCUMENTATION

规则怎么下发，
接口里都有答案

加载只是第一步。真正的 SUSFS 行为由用户态通过 /proc/susfs_* 控制；所有写入成功返回长度，失败返回负 errno。

/proc/susfs_kstat

伪装 stat() / statx() / maps 中的 inode 与时间戳。

 /proc/susfs_open_redirect

把指定 open() 重定向到另一个文件，并覆盖反向面。

 /proc/susfs_path

sus_path 规则表。直接 cat 即可查看当前隐藏清单。

 /proc/susfs_map

按 inode 隐藏 mmap 的真实文件，覆盖 maps / pagemap 等视图。

 /proc/susfs_hide_mounts

定义哪些挂载属于“我们的”，决定最终隐藏的挂载集合。

 /proc/susfs_hide_modules

按名字把其他内核模块从 /proc/modules 中移除。

前往 Issues
需要重新编译内核吗？

不需要。LKM 版本以 .ko 形式运行，不修改内核源码，也不替换 GKI。你只需要选择与设备 KMI 匹配的产物，然后载入。

如何确认设备应该用哪个 KMI？

运行 getprop ro.build.version.release 与 cat /proc/sys/kernel/osrelease。例如 release 为 6.6.30-android15-…，对应 android15-6.6。模块 ZIP 会自动完成同样的匹配。

非 KernelSU 设备可以用吗？

可以。Release 附带独立的 susfs_insmod 加载器，在 root 环境中直接载入 .ko。注意它仍然要求设备满足 Android 12+、arm64-v8a 与对应 GKI 版本。

刷入模块后没有 /proc/susfs_* 怎么办？

先确认模块确实以 expose_proc=1 载入，并检查 lsmod | grep susfs。如果系统已有内置 SUSFS，模块会跳过加载；此时应由现有接口负责。模块本身不会创建规则。

模块会修改系统分区吗？

不会写入内核分区。手动方式只在运行时载入 LKM；模块 ZIP 也只增加 KernelSU 模块目录下的加载脚本与产物，停用或删除后重启即可恢复。

为什么下载链接指向 GitHub Release？

本站不单独发布二进制，实际构建产物由 inforcqb/susfs4ksu-for-lkm 的 Release 提供。站点不镜像、不重打包这些文件，下载后请自行校验来源。
